# Maple Companion

컴퓨터를 쓴 시간만큼 메이플스토리 캐릭터가 자라는 데스크톱 컴패니언. 비공식·비상업 팬메이드이며 메이플스토리 관련 권리는 NEXON 에 있다.

## 설치

macOS(Apple Silicon·Intel 둘 다)와 Windows 10·11(x64)용이 있다. 둘 다 [Releases 최신 버전](https://github.com/blueeeeg/maple-companion/releases/latest)에서 받는다.

### macOS

1. Releases 에서 `.dmg` 를 받는다. `.zip` 을 받아도 된다
2. `.dmg` 를 열고 `Maple Companion` 을 응용 프로그램 폴더로 끌어 놓는다. `.zip` 이면 풀어서 나온 앱을 응용 프로그램 폴더로 옮긴다
3. 처음 열 때 「확인되지 않은 개발자」 경고가 뜬다. Apple 공증(notarization)을 받지 않은 앱이라서다. 응용 프로그램 폴더에서 앱을 우클릭 → 「열기」 → 「열기」를 누르면 다음부터는 그냥 열린다. 그래도 안 열리면 터미널에서 아래를 한 번 실행한다

```bash
xattr -dr com.apple.quarantine "/Applications/Maple Companion.app"
```

### Windows

Windows 판은 CI 에서 빌드만 했고 실제 PC 에서는 아직 확인하지 않았다.

1. Releases 에서 `Maple.Companion_{버전}_x64-setup.exe` 를 받아 실행한다. `.msi` 를 써도 된다
2. 코드 서명을 하지 않은 앱이라 「Windows의 PC 보호」 창이 뜬다. 「추가 정보」를 누르고 「실행」을 누른다
3. 트레이 아이콘이 작업표시줄 오른쪽의 숨겨진 아이콘(^) 안에 들어가 있을 수 있다. 끌어서 작업표시줄로 꺼내 두면 바로 보인다

Windows 에서는 아래 설명의 「메뉴바」를 작업표시줄 오른쪽 알림 영역으로, Dock 을 작업표시줄로 읽는다. 펫 창은 작업표시줄 바로 위 오른쪽 구석에 뜨고, 메뉴바 모드 창은 트레이 아이콘 위로 열린다. 메뉴바 글자 대신 트레이 아이콘 툴팁에 상태가 나온다.

### 처음 실행

처음에는 화면 구석의 작은 창(펫 모드)으로 뜨고 Dock 에는 안 보인다. 메뉴바의 트레이 아이콘을 누르면(왼쪽·오른쪽 클릭 같음) 메뉴가 열린다. 메뉴 맨 위 항목으로 캐릭터(메뉴바 모드에서는 창)를 숨기거나 다시 띄우고, 펫 모드·메뉴바 모드를 바꾸거나(지금 모드에 체크) 「종료」로 끈다. 숨겨도 앱은 계속 돌아가서 활동 시간·사냥·BGM 이 이어진다. 캐릭터·맵·소리는 실행 중에 [maplestory.io](https://maplestory.io) 에서 받아 오므로 인터넷이 필요하다.

## 업데이트

**v0.1.0 에는 업데이트 기능이 없다.** v0.1.0 을 쓰고 있으면 다음 버전 한 번은 위 「설치」대로 손으로 받아 덮어쓴다(앱을 끄고 새 앱으로 바꿔 넣는다). 캐릭터는 앱 밖의 저장 폴더(아래 「저장 위치」)에 있어서 그대로 남는다. 그 다음 버전부터는 앱 안에서 업데이트한다.

- 앱을 켜고 30초쯤 뒤에 한 번, 그 뒤로 6시간마다 [Releases 최신 버전](https://github.com/blueeeeg/maple-companion/releases/latest)의 `latest.json` 을 본다. 인터넷이 안 되면 아무것도 띄우지 않고 30분 뒤에 다시 본다
- 새 버전이 있으면 OS 알림 「새 버전 vX.Y.Z 가 나왔어요」를 띄운다. 버전마다 한 번만 띄우고 앱을 다시 켜도 같은 버전은 다시 알리지 않는다. 전직 알림 설정과 상관없이 뜬다. 알림을 누르면 창이 열리고 트레이 메뉴로 안내한다
- 트레이 메뉴 「종료」 바로 위 항목이 업데이트 버튼이다. 평소에는 「현재 버전 v0.1.1」 처럼 지금 버전을 보여 주고 누를 수 없다. 새 버전이 있으면 「업데이트 (v0.1.2)」 로 바뀐다
- 누르면 받아서 설치하고 앱을 다시 켠다. 받는 동안 그 항목과 메뉴바 글자(Windows 는 트레이 툴팁)에 「업데이트 중… 42%」 가 나온다. 다시 켜기 전에 저장 파일을 마저 쓴다. 실패하면 항목이 「업데이트 실패 · 다시 시도 (v0.1.2)」 로 바뀌어 다시 누를 수 있다
- 받은 파일은 앱에 넣어 둔 공개키로 서명을 확인하고, 맞지 않으면 설치하지 않는다(`tauri-plugin-updater`)
- macOS 는 앱 번들을 통째로 바꿔 넣는다. 앱을 둔 폴더에 쓸 권한이 없으면 macOS 가 관리자 암호를 묻는다. Windows 는 설치 프로그램(`-setup.exe`)이 진행 창만 띄워 설치하고 앱을 다시 켠다. Windows 업데이트는 실제 PC 에서 아직 확인하지 않았다

## 기능

- 키보드·마우스 입력이 있는 동안(기본 2분 넘게 입력이 없으면 멈춤) 경험치가 쌓인다
- 초보자에서 6차 전직(Lv.260)까지. Lv.10 이 되면 원작 NPC 대화창이 뜬다. 메이플 아일랜드의 마이가 길을 묻고, 고른 직업의 전직관(주먹펴고 일어서·하인즈·헬레나·다크로드·카이린)이 「예」를 받으면 전직한다. 대화를 그만둬도 HUD 의 「전직 가능!」 버튼으로 다시 연다
- Lv.30(2차 전직)에는 같은 전직관이 원작 모험가 2차 갈래를 묻는다. 고른 갈래가 3·4차를 정하고 5·6차는 4차 이름을 그대로 쓴다. 갈래를 고를 때까지는 레벨이 넘어도 1차에 머물고, 대화를 그만두면 HUD 의 「전직 가능!」 버튼으로 다시 연다. 직업을 Lv.30 넘어서 골랐으면 직업을 고른 뒤 바로 갈래를 묻는다(`src/game/jobs.ts` `JOB_BRANCHES`)
  - 전사: 파이터→크루세이더→히어로 / 페이지→나이트→팔라딘 / 스피어맨→버서커→다크나이트
  - 마법사: 위자드(불,독)→메이지(불,독)→아크메이지(불,독) / 위자드(썬,콜)→메이지(썬,콜)→아크메이지(썬,콜) / 클레릭→프리스트→비숍
  - 궁수: 헌터→레인저→보우마스터 / 사수→저격수→신궁
  - 도적: 어쌔신→허밋→나이트로드 / 시프→시프마스터→섀도어
  - 해적: 인파이터→버커니어→바이퍼 / 건슬링어→발키리→캡틴
  - 이름은 KMS 389 전직 퀘스트(1411~1446·32220~32231)와 스킬북 이름(`String/Skill.img/{직업 번호}/bookName`)으로 맞췄다. 스피어맨의 3차는 지금 KMS 에서 드래곤나이트가 아니라 버서커다. 패스파인더·듀얼블레이드·캐논슈터는 따로 만드는 직업이라 넣지 않았다
  - 갈래마다 제 무기를 쥔다. 2차는 Lv.10~30 무기, 3차부터는 메이플 무기다: 한손검·두손 둔기·창 / 스태프·완드·스태프 / 활·석궁 / 아대·단검 / 너클·총. 방어구는 원작처럼 계열 단위라 갈래가 같이 입는다. 창은 `stand2`·`walk2`, 석궁·두손 둔기는 `walk2` 에만 무기 그림이 있어서 그 동작으로 서고 걷는다. 원거리 갈래(총·석궁·지팡이·아대)는 근접 갈래보다 멀리 서서 싸운다
  - 보상·사냥 속도는 갈래와 상관없다. 이름·모습·스킬만 다르다
- 2차 갈래를 고른 뒤로는 3차부터 6차 전직이 레벨이 되면 저절로 되고, 같은 전직관이 축하 대화를 띄운다. 축하 창은 화면을 어둡게 하지 않고 게임도 멈추지 않는다. 대화가 겹치면 앞 대화가 끝난 뒤에 연다
- 캐릭터 정보창 「직업」 줄의 「바꾸기」로 같은 계열의 다른 2차 갈래로 바꾼다. 2차 갈래를 고른 뒤에만 나온다. 계열(전사·마법사…)은 못 바꾼다. 캐릭터 슬롯 여섯 칸이 계열을 고르는 몫이라서다
  - 「직업」 줄은 차수 없이 이름만 적는다(「캡틴」). 차수는 「전직」 줄에 있고, 가장 긴 이름(아크메이지(썬,콜))도 버튼과 한 줄에 다 들어간다. 버튼에 마우스를 올리면 「같은 계열 다른 직업으로 · 50,000 메소」, 무료 한 번이 남았으면 「… · 한 번 무료」라고 뜬다
  - 2차 갈래를 고르면 HUD 알림으로 「이제 캐릭터 정보창 「직업」 줄에서 같은 계열 다른 직업으로 바꿀 수 있어요」를 한 번 띄운다. 이 안내를 넣기 전에 이미 2차를 지난 캐릭터는 업데이트 뒤 처음 맵에 들어올 때 한 번 띄운다. 전직관 대화가 떠 있거나 앞 알림(「전직 완료」 등)이 아직 보이면 그것이 끝난 뒤에 띄운다
  - 한 번에 50,000 메소(`JOB_CHANGE_MESO`). 전직관 대화에 값과 가진 메소를 적고, 모자라면 갈래를 못 누르게 하고 얼마나 모자란지 빨갛게 적는다. 갈래를 누르면 「예」로 한 번 더 묻고 그때 메소를 낸다
  - 레벨·경험치·기록·옷장·전직 날짜는 그대로다. 이름·장비·스킬이 바로 새 갈래 것이 되고, 스킬창에서 고른 사냥 스킬은 자동으로 돌아간다
  - 바꾼 기록은 캐릭터 정보창 「전직」 쪽의 전직 날짜 아래에 「10-27 인파이터 → 건슬링어」처럼 쌓인다. 이름은 지금 차수의 이름이다
- 갈래가 생기기 전 판에서 2차를 이미 한 캐릭터는 그때 하나뿐이던 길(히어로·아크메이지(불,독)·보우마스터·나이트로드·바이퍼)로 읽는다. 대신 다음에 맵에 들어오면 전직관이 한 번 무료로 「직업 바꾸기」를 연다. 「지금 그대로」를 고르거나 대화를 닫으면 지금 갈래로 정하고 다시 묻지 않는다
- 직업 고르기(Lv.10)·2차 갈래 고르기(Lv.30)와 그 밖의 전직은 창이 숨어 있거나 다른 앱을 보고 있으면 OS 알림으로 알린다. 같은 일은 한 번만 알리고, 레벨업·보스는 알리지 않는다. 알림을 누르면 창이 열리고 직업·갈래 고르기 대화가 닫혀 있었으면 다시 연다. 직업이나 갈래를 아직 안 골랐으면 메뉴바 글자가 「Lv.10 · 전직 가능!」 이 된다(Windows 는 트레이 툴팁)
- 캐릭터가 실제 마을 맵의 발판 위를 돌아다니고 마을 BGM 이 나온다. 기본 8분마다 다른 마을로 옮긴다
- 마을마다 원작 포털로 이어진 사냥터가 최대 세 곳 있다(`src/game/routeData.ts`). 한 맵에서 몬스터를 2마리 잡거나 3분이 지나면(도착하고 1분은 그대로) 캐릭터가 포털까지 가서 들어가고, 이어진 맵의 포털에서 나온다. 포털이 윗층에 있으면 원작 발판·사다리·로프를 따라 뛰어오르고, 떨어지고, 아래 점프하고, 사다리·로프를 타고 간다. 윗층 포털로 나오면 사냥하는 바닥까지 같은 식으로 내려온다. 사냥터로 드나드는 포털은 원작처럼 마을·사냥터 맵에 늘 떠 있고, 마우스를 올리거나 누르면 가는 맵 이름이 뜬다. 사냥터에서는 왔던 포털로 돌아가거나 더 안쪽 사냥터로 간다. 사냥터 몬스터는 그 맵에 실제로 나오는 몬스터이고 경험치는 마을 기준 그대로다. 메소 보상은 표시 마을이 아니라 레벨 기준 최고 마을(열린 마을 중 가장 높은 마을)을 쓴다. 사냥터 BGM 은 그 맵 곡이다
  - 사냥 중·보스전 중에는 옮기지 않는다. 사냥터에서 보스를 만나면 보스를 잡고 그 사냥터로 돌아온다
  - 설정 「마을」이 「머물기」면 그 마을과 그 마을 사냥터 안에서만 오간다. 「돌기」면 고른 시간이 되었을 때 사냥터에 있어도 지금처럼 바로 다음 마을 맵으로 옮긴다
  - 사냥터 맵을 못 받아 오면 그 사냥터는 다른 마을로 갈 때까지 건너뛴다. 마을에 들어가면 그 마을 사냥터 맵을 뒤에서 하나씩 미리 받아 둔다
  - 몹이 없는 통로 맵(오르비스탑입구·무릉 사원·세르니움 성문 등)은 사냥하지 않고 걸어서 지나간다. 통로에 들어서면 바로 다음 포털까지 걸어가 이어 탄다. 통로 맵에도 드나드는 포털이 늘 떠 있다. 이어 가다 맵을 못 받아 오면 그 맵에 남았다가 다음 차례에 바로 다른 곳으로 옮긴다
- 원작처럼 캐릭터 발밑에 이름표(반투명 검은 상자에 흰 글자)가 따라다닌다. 원작 기본 이름표는 그림이 아니라 클라이언트가 그려서 같은 모양으로 그린다. 앞 레이어보다 위, 대미지 숫자보다 아래에 보이고 경험치 바와 겹치지 않는다
- 기본 활동 3분마다 그 마을 몬스터가 나와 자동으로 사냥한다. 몬스터를 누르면 추가 타격
- 기본 20번째 사냥마다(활동 약 1시간) 보스가 나온다. 잡을 수 있는 보스를 한 바퀴씩 돌아가며 무작위 순서로 고르고(보스 도전 창에서 다음 보스를 지정할 수 있다), 그 보스를 잡는 원작 맵으로 옮겨 20~40초 싸운 뒤 마을로 돌아온다. 기본 설정이면 경험치는 보통 몬스터의 20배, 메소는 10배. 창을 닫아 둔 사이 돌아온 보스 차례는 애니메이션 없이 정산한다
- 캐릭터는 6명까지. 캐릭터마다 이름·외형(헤어·얼굴·피부)·레벨·직업·메소·몬스터 기록을 따로 가진다

## 설정

HUD 오른쪽 ⚙️ 메뉴의 「설정」이나 트레이 메뉴 「설정」으로 연다. HUD 가 좁아서(긴 직업 이름·휴식 중·스탯·스킬 버튼이 겹치면 이미 꽉 찬다) 소리 끄기·장비·BGM 고르기·설정·캐릭터 선택은 ⚙️ 버튼 하나의 메뉴로 묶었다. 설정 창은 캐시샵처럼 같은 창 안에 뜨고 열려 있는 동안 맵과 BGM 이 멈춘다. 「확인」을 눌러야 저장되고 「취소」·Esc·창 밖 클릭은 고친 것을 버린다. 설정은 캐릭터마다가 아니라 앱 전체에 하나이고 캐릭터 목록과 같은 저장 파일(아래 「저장 위치」)에 판 번호와 함께 저장한다. 깨졌거나 목록에 없는 값은 기본값으로 읽는다(`src/game/settings.ts`).

| 마을 | 돌기(4·8·15·30분마다) / 머물기(지금 캐릭터에게 열린 마을 하나) | 돌기 · 8분 |
| 배경음악 | 음량 0~100, 음소거 | 35 · 켜기 |
| 레벨업 | 이펙트 원본 / 작게(0.65배), 전직 알림 켜기·끄기 | 원본 · 켜기 |
| 자리 비움 | 입력 없이 1·2·5·10분 지나면 활동 시간(성장) 멈춤 | 2분 |

- 몬스터 주기를 바꿔도 시간당 EXP·메소는 같다. 한 마리 보상(경험치 60, 메소)을 「주기 ÷ 3분」 배로 준다. 1분이면 한 마리 20, 10분이면 200 이다
- 보스 버튼은 「10번마다」처럼 사냥 차례로 적는다. 보통 몬스터 몇 마리를 잡아야 나오는 것이 아니고 활동 시간으로 온다(몬스터 주기 × 보스 간격). 안내 줄에 지금 몬스터 주기로 잰 시간(기본 「활동 약 1시간마다」)을 같이 적고, 몬스터·보스 값을 바꾸면 바로 따라 바뀐다
- 보스 간격을 바꿔도 시간당 보상은 같다. 보스는 지난 보스 뒤로 사냥한 시간만큼 보스 몫을 모았다가 한 번에 준다. 몫은 그 시간의 보통 몬스터 보상에 경험치는 19/20, 메소는 9/20 을 곱한 값이다. 기본 설정이면 보스가 경험치 20배·메소 10배를 주는 값이고, 10번마다면 10.5배·5.5배, 40번마다면 39배·19배다
- 그래서 시간당 경험치는 어느 조합이든 활동 3600 + 사냥 2340(보통 몬스터 1200 + 보스 몫 1140)이다. 보스를 끄면 보스 몫(시간당 EXP 19%·메소 31%)을, 몬스터를 끄면 보스도 안 나오고 사냥 몫 전부(시간당 EXP 39%·메소 전부)를 못 받는다. 활동 시간 경험치는 그대로 쌓인다. 레벨에 맞는 보스가 없는 Lv.10 미만은 보스 차례가 보통 몬스터로 지나가고 모인 몫은 첫 보스 때 받는다
- 사냥 진행은 마리 수가 아니라 사냥으로 바꾼 활동 시간(초)으로 센다(`huntSeconds`). 주기를 바꿔도 쌓인 진행이 초 단위로 이어지니 몬스터가 몰려나오거나 한참 안 나오지 않는다. 주기를 줄여 쌓인 진행이 새 주기 여러 번 몫이 되면 한 마리만 바로 나오고 나머지 몫은 그 한 마리 보상에 보통 몬스터 비율로 얹는다. 몬스터를 꺼 둔 동안의 활동 시간은 사냥으로 치지 않아서 다시 켜도 그동안의 몬스터가 한꺼번에 나오지 않는다. 예전 저장은 「치른 사냥 수 × 3분」 으로 옮긴다
- `src/game/settings.test.ts` 가 1·3·5·10분 × 10·20·40번 열두 조합을 20시간 돌려 시간당 경험치가 똑같고 메소는 반올림 차이(0.5% 미만)뿐인 것, 주기·보스 간격을 수시로 바꿔도 안 쓴 진행만큼만 차이 나는 것을 확인한다
- 자리 비움 판정은 Rust(`activity.rs`)가 한다. 프론트가 `set_idle_limit` 명령으로 넘기면 activity.json 에 남겨 다음 실행에는 프론트가 뜨기 전부터 그 값으로 잰다. 브라우저로 볼 때는 대체 구현이 같은 값을 쓴다
- 「마을」 줄은 캐릭터가 마을을 고르는 방식 하나만 정한다. 「돌기」를 고르면 그 줄에 시간 버튼이, 「머물기」를 고르면 ◀ 마을 ▶ 이 뜬다. 고르지 않은 쪽 버튼은 안 보인다
- 돌기는 고른 시간마다 열린 마을을 셔플 백으로 고루 돌아가며 옮기고(같은 마을이 연속되지 않게 주기 경계에서 조정), 새 마을이 열리면 바로 그 마을로 간다. 안내 줄은 「8분마다 열린 마을을 고루 돌아다녀요」
- 머물기는 그 마을과 그 마을 사냥터에서만 지내고 새 마을이 열려도 옮기지 않는다. 처음 누르면 지금 서 있는 마을이 골라져 있고 ◀ ▶ 는 지금 캐릭터에게 열린 마을만 넘긴다. 설정 창을 연 채 돌기로 바꿨다 다시 머물기를 누르면 아까 고른 마을로 돌아온다. 머무는 동안은 안내 줄에 늘 「커닝시티와 그 사냥터에만 있어요」(사냥터가 없는 마을은 「리스항구에만 있어요」)처럼 뜬다
- 설정은 앱 전체에 하나라 다른 캐릭터로 고른 마을이 지금 캐릭터에게 아직 안 열렸을 수 있다. 그 캐릭터는 고른 시간마다 돌고, ◀ ▶ 자리에 「리프레(안 열림)」, 안내 줄에 「리프레는 이 캐릭터에게 아직 안 열려서 8분마다 열린 마을을 고루 돌아다녀요」가 뜬다. 넘기면 그 마을은 목록에서 빠진다
- 저장에는 머물 마을(`pinnedTownId`, 돌기면 `null`)과 도는 시간만 남긴다. 예전 판의 「마을 이동 · 자동」 체크(`townRotate`)는 없앴다. 예전에 마을을 고정해 뒀으면 그대로 머문다. 고정 없이 「자동」만 꺼 뒀으면 그때 서 있던 마을에 머물렀는데 그 마을은 저장되지 않았고 켤 때마다 최근 마을 중에서 골랐다. 그래서 지금 캐릭터에게 가장 최근에 열린 마을에 머물기로 옮긴다(`src/platform/gameState.ts` 가 레벨을 넘긴다). 돌기로 옮기면 멈춰 두었던 캐릭터가 갑자기 돌아다니게 돼서 고르지 않았다
- 배경음악 음소거는 HUD 메뉴의 「소리 끄기」와 같은 값이다. 음량을 0 으로 둔 채 「소리 켜기」를 누르면 기본 음량으로 돌아온다
- 「BGM 고르기」 창에서 고른 것도 같은 설정에 저장한다. 설정 창과 달리 「확인」 없이 고르는 즉시 저장된다. 트는 방식 `bgmMode`(`map`·`repeat`·`shuffle`, 기본 `map`), 반복할 곡 `bgmTrack`(`Bgm00/FloralLife` 같은 곡 경로, 기본 `null`), 즐겨찾기 `bgmFavorites`(곡 경로 목록, 기본 빈 목록)다. 예전 판 저장에는 이 값이 없어서 맵 따라가기로 읽는다. 곡 경로 꼴이 아닌 값은 버리고 겹친 즐겨찾기는 하나로 친다. 고른 곡이 없는 `repeat` 는 `map` 으로 읽는다. 즐겨찾기가 빈 `shuffle` 은 고른 대로 남기고, 트는 쪽이 맵 따라가기로 튼다
- 전직 알림은 설정 창에 줄을 더 넣을 높이가 없어 레벨업 줄에 있다. 알림은 `tauri-plugin-notification` 으로 권한을 묻고 띄운다. macOS 는 알림에 앱 아이콘 그림을 넣으려고 Rust 가 직접 보낸다(아래 「OS 알림의 그림」). 처음 알릴 때 권한을 묻는다. macOS 는 처음 알림이 갈 때 시스템이 허용 여부를 묻고, 거절했으면 시스템 설정 → 알림에서 켠다. Windows 는 따로 묻지 않고, 설치 프로그램이 시작 메뉴 바로가기에 앱 ID(`com.maplecompanion.app`)를 붙여 둬야 알림이 뜬다. 그래서 설치한 앱에서만 앱 이름으로 뜨고 `pnpm tauri dev` 에서는 PowerShell 이름으로 뜬다. 꺼져 있으면 설정 → 시스템 → 알림에서 켠다. 브라우저로 볼 때는 웹 Notification 으로 띄운다

설정 창은 원작 시스템 옵션 창 `UI/UIWindow2.img/SysOpt/backgrnd`(283×354)를 원본 크기로 쓰되 위 198px·아래 32px 띠만 잘라 230 높이로 잇는다. 확인 `MemoInGame/Get/BtOK`·취소 `Basic.img/BtCancel4`(40×16), 음량 슬라이더 `Basic.img/HScr8`(양 끝 `prev0`·`next0`, 가운데 `base`, 손잡이 `thumb0`·`thumb1`), 체크 상자 `Basic.img/CheckBox0`(11×11)도 `_Canvas` 로 받아 원본 크기로 쓴다. 안쪽 회색 판과 항목 칸은 원작 옵션 창 색을 CSS 로 옮겼다. 그림을 못 받으면 같은 배치의 어두운 창과 글자 버튼으로 남는다.

## 전력 사용

하루 종일 켜 두는 앱이라 할 일이 없으면 그리지 않는다.

- **창을 숨기면** 맵을 그리지 않는다(Pixi 티커와 rAF 모두 멈춤). HUD 의 CSS 애니메이션도 멈춘다. 활동 시간은 Rust 가 5초마다 재서 쌓고, 사냥 정산은 다시 보일 때 한 번에 한다. 숨긴 동안 틱은 2초 대신 10초마다 돌아서 알림·트레이 글자가 몇 초 늦게 바뀔 수 있다. BGM 은 그대로 나온다
- **팝업**(캐시샵·정보·스킬·보스·설정·BGM 고르기)이 맵을 가리면 맵을 멈춘다
- **서 있을 때**(사냥·스킬·페이드·카메라 이동·이펙트가 없을 때)는 rAF 를 끄고 타이머로 10fps 만 그린다. 늘 도는 포털 프레임이 100ms 라 10fps 로도 빠지는 프레임이 없다. 원작 딜레이가 100ms 보다 짧은 그림이 돌고 있으면 낮추지 않는다(`src/scene/framePolicy.ts`). 의자에 앉아 있는 동안은 서 있는 것과 같아서 한 장짜리 의자(하늘색 나무 의자)·버섯친구 의자(180ms)는 10fps 다. 의자 프레임도 포털처럼 세서 블루 드래곤 의자(96ms)에 앉아 있는 동안은 30fps 다. 탄 채 서 있으면 탈것 서기 딜레이를 센다. 멧돼지(180ms)는 10fps, 힐라와 설원을·샤레니안의 악마(90ms)는 30fps 다
- **걷기·사냥·스킬·맵 이동** 중에는 30fps 로 그린다
- 캐릭터 저장은 틱(2초)마다 오지만 파일은 10초에 한 번까지만 쓴다. 쓸 때마다 fsync 로 디스크를 깨우기 때문이다

## 저장 위치

앱(Tauri)은 데이터를 macOS 는 `~/Library/Application Support/com.maplecompanion.app/`, Windows 는 `%APPDATA%\com.maplecompanion.app\`(`C:\Users\{사용자}\AppData\Roaming\com.maplecompanion.app\`)에 둔다. 개발 빌드(`pnpm tauri dev`)와 배포 앱이 같은 폴더를 쓴다.

| 파일 | 내용 |
|---|---|
| `game-state.json` | 캐릭터 목록(레벨·직업·메소·옷장·장비 컬렉션·의자·탈것·사냥 스킬·전직 날짜 등)과 설정 |
| `game-state.json.bak` | 바로 앞에 저장한 `game-state.json`. 본 파일을 못 읽으면 이것으로 연다 |
| `activity.json` | 앱 전체 활동 시간, 창 모드·크기, 자리 비움 판정 시간 |
| `tray-icon.png`·`custom-tray-icon.png` | 트레이 아이콘 |
| `app-icon-applied.txt` | macOS 앱 아이콘을 마지막으로 붙인 그림의 해시, 또는 붙이지 못한 기록 |
| `bgm/` | 한 번 받은 BGM. 곡 경로로 이름을 짓는다(`Bgm00/FloralLife` → `KMS-389-Bgm00-FloralLife.mp3`, 빈칸·따옴표 같은 글자는 `-20` 처럼 바이트 16진수). 여러 맵이 같은 곡이면 한 파일이다. 모두 합쳐 300MB 를 넘으면 오래 안 들은 곡부터 지운다. 지워도 되고, 지우면 다음에 틀 때 다시 받는다 |

그림·데이터 캐시는 위 폴더가 아니라 WebView 의 IndexedDB(`maple-companion-cache:KMS-389`)에 있다. macOS 는 `~/Library/WebKit/com.maplecompanion.app/WebsiteData/IndexedDB/`, Windows 는 `%LOCALAPPDATA%\com.maplecompanion.app\EBWebView\` 아래다. 모두 maplestory.io 에서 다시 받을 수 있는 것이라 지워도 캐릭터는 그대로다.

| 키 | 내용 | 예산 |
|---|---|---|
| `KMS-389:art:{요청 주소}` | 맵 전체·레이어 렌더, 맵·몹 정보 JSON, 캐릭터·몹 GIF·프레임, 포털·대미지 숫자·의자 그림, 미리 받은 사냥터 맵(`src/maple/artStore.ts`), 창 틀·버튼·HUD 단축 버튼 같은 화면 그림(`src/ui/art.ts`) | 400MB, 32MB 넘는 응답은 안 남김 |
| `KMS-389:art-index` | 위 그림의 크기·마지막으로 쓴 때 | — |
| `KMS-389:crop:{판}:{요청 주소}` | 위 그림에서 canvas 로 떼어 낸 것(HUD 스탯·스킬·보스 글자, 버튼 띠, 보스 목록 빈 틀)의 PNG data URL(`src/ui/art.ts` `cropArt`) | 없음(작다) |
| `KMS-389:skill:{ID}` | 스킬 데이터(`src/maple/skillStore.ts`) | 60MB, 5MB 넘는 스킬은 안 남김 |
| 주소 그대로 | 캐시샵 목록·아이콘·미리보기, 스킬·보스 아이콘, 맵 BGM 이름(`src/ui/cashAssets.ts`) | 없음(작다) |

- 예산을 넘으면 마지막으로 쓴 때가 오래된 것부터 지운다. 지금 맵·옮겨 가기 전 마을과 지금 캐릭터 모습의 그림, `UI/` 아래 화면 그림은 건너뛴다
- 화면 그림(캐릭터 선택·캐시샵·창 틀·버튼·HUD)은 `<img>`·CSS 에 maplestory.io 주소를 바로 걸지 않고, fetch 로 받아 위 `art` 키에 남긴 뒤 blob 주소로 건다(`src/ui/art.ts`). 그래서 한 번 받은 화면은 다음 실행부터 네트워크 없이 원작 그림으로 뜬다. 떼어 쓰는 그림은 뗀 결과도 `crop` 키에 남기고, 떼는 법이 바뀌면 `{판}` 이 바뀌어 새로 뗀다
- 화면 그림을 못 받으면 글자·기본 모양으로 두고 거기서 멈추지 않는다. 2초·4초 쉬며 세 번 받아 보고, 그래도 못 받으면 15초·30초·1분·2분·5분(이후 5분마다) 뒤에 다시 받는다. 창이 다시 보이거나(`visibilitychange`) 네트워크가 돌아오면(`online`), 또 그 그림을 쓰는 창을 다시 열면 기다리지 않고 바로 받는다. 404 같은 「그림이 없다」 답만 다시 받지 않는다
- KMS 버전이 바뀌면 DB 이름이 바뀌고 앞 버전 DB 는 통째로 지운다. 맵 보정값(localStorage `maple-companion:calibration:KMS-389:{맵 ID}`)도 버전마다 따로 둔다
- **비우기**: 앱을 끄고 위 `IndexedDB` 폴더를 지운다. 브라우저(`pnpm dev`)에서는 개발자 도구 Application → IndexedDB 에서 지운다

- HUD 의 보스 버튼(원작 메뉴의 「보스」 글자)으로 보스 도전 창을 연다. 원작 보스 목록 모양으로 보스 15마리를 레벨 순으로 늘어놓고 보스마다 처치 수를 적는다. 아직 레벨이 모자란 보스는 회색에 「Lv.N부터」다. 열려 있는 동안 맵과 BGM 이 멈추고, 닫기는 ✕·Esc·창 밖 클릭(`src/ui/bossWindow.ts`, `src/game/bossChallenge.ts`)
  - 「다음 보스 지정」: 다음 보스 차례에 무작위 대신 이 보스가 나온다. 캐릭터마다 저장되고, 그 보스를 잡으면 지워진다. 창에 「다음 보스 · 핑크빈 [취소]」 로 보이고 목록 칸에 「지정」 표시가 붙는다. 보상은 어느 보스든 같다
  - 「지금 도전」: 보스 차례가 와 있으면(보스 몫이 다 찼으면) 그 차례를 써서 지금 싸우고 보통 보스와 같은 보상을 받는다. 차례가 아니면 연습전이다. 시작 전에 「경험치·메소를 받지 않고 처치 기록에도 남지 않아요」 와 다음 보스까지 남은 활동 시간(「약 23분」)을 보여 주고, 싸우는 동안 보스 게이지 아래에 원작 PRACTICE MODE 표시를 띄운다. 연습전은 보스 몫·사냥 시계를 건드리지 않는다
  - 보스를 꺼 두면(설정 「보스 끄기」·몬스터 끄기) 연습전만 할 수 있다고 적는다. 몬스터·보스와 싸우는 중이거나 맵을 옮기는 중이면 「지금 도전」 을 막고 까닭을 적는다
  - 시간당 경험치·메소는 그대로다. 「지금 도전」 은 사냥 시계를 한 번 앞당겨 쓸 뿐이라 같은 시간이 지나면 같은 수의 사냥을 치른다. `src/game/bossChallenge.test.ts` 가 10시간을 돌려 보스 지정·「지금 도전」·연습전을 섞어도 경험치·메소 합계가 같은 것과 연습전이 캐릭터 값을 하나도 안 바꾸는 것을 확인한다
- 저장은 바뀌면 0.3초쯤 모았다가 쓰고, 쓴 뒤 10초 동안 온 변경은 모아서 한 번에 쓴다. 「종료」·업데이트로 끌 때는 남은 것을 바로 쓴다. 임시 파일에 다 쓴 뒤 바꿔치기해서 도중에 꺼져도 반만 쓰인 파일이 남지 않는다(`src-tauri/src/game_state.rs`)
- 본 파일이 깨져 있으면 `game-state.json.corrupt` 로 복사해 두고 `.bak` 으로 연다
- **백업**: 앱을 끄고 위 폴더를 통째로 복사한다. 되돌릴 때는 앱을 끄고 복사해 둔 `game-state.json` 을 제자리에 넣는다
- **초기화**: 앱을 끄고 `game-state.json`·`game-state.json.bak` 을 지운다. 활동 시간까지 지우려면 `activity.json` 도 지운다
- 개발 빌드와 배포 앱을 **동시에** 켜지 않는다. 둘 다 같은 파일에 자기 메모리의 목록을 통째로 써서, 나중에 쓴 쪽이 다른 쪽에서 만든 변경을 덮는다

캐릭터 하나에 남는 값 중 이 판에서 더한 것(`src/game/characters.ts` `Character`). 예전 저장에 없으면 읽을 때 채운다(`normalizeRoster`).

- `bossBag`: 이번 주기에 아직 나오지 않은 보스 몹 ID 배열. 비면 다음 보스 차례에 자격 있는 보스를 모두 섞어 새 주기로 채운다. 없거나 배열이 아니면 빈 배열로 읽는다
- `lastBossId`: 마지막으로 셔플 백에서 꺼낸 보스 몹 ID. 새 주기 첫 보스가 같은 보스로 연속되지 않게 쓴다. 없거나 숫자가 아니면 `null` 로 읽는다
- `townBag`: 이번 주기에 아직 방문하지 않은 마을 ID 배열. 비면 다음 마을 차례에 자격 있는 마을을 모두 섞어 새 주기로 채운다. 없거나 배열이 아니면 빈 배열로 읽는다
- `lastTownId`: 마지막으로 셔플 백에서 꺼낸 마을 ID. 새 주기 첫 마을이 같은 마을로 연속되지 않게 쓴다. 없거나 문자열이 아니면 `null` 로 읽는다
- `jobBranch`: 2차 전직 때 고른 갈래(`hero`·`paladin`·`darkKnight`·`firePoison`·`iceLightning`·`bishop`·`bowmaster`·`marksman`·`nightLord`·`shadower`·`viper`·`captain`). 아직 안 골랐으면 `null` 이고 그동안은 1차다. 칸이 없던 예전 저장은 2차를 이미 했으면 그 계열의 첫 갈래, 아니면 `null` 로 읽는다. 다른 계열 갈래나 모르는 값은 `null`
- `freeJobChange`: 칸이 없던 예전 저장이라 갈래를 저절로 받은 캐릭터. `true` 면 맵에 들어올 때 무료 「직업 바꾸기」를 한 번 연다. 답하거나 닫으면 `false`
- `jobChangeHintShown`: 「직업」 줄에서 갈래를 바꿀 수 있다는 HUD 안내를 띄웠는지. 칸이 없거나 `true` 가 아니면 `false` 로 읽어서, 이미 2차를 지난 캐릭터도 한 번 안내한다
- `jobHistory`: 2차 갈래를 바꾼 기록 `{ at, from, to }` 배열(시각 ms·갈래 ID). 처음 고른 것은 전직이라 `advancedAt` 에만 있다. 없거나 깨진 항목은 빼고 읽는다
- `advancedAt`: 차수 → 전직한 시각(ms). `null` 은 기록을 시작하기 전에 이미 한 전직이라 날짜를 모른다는 뜻이다. 칸이 없던 예전 저장은 그때까지 오른 차수를 모두 `null` 로 채우고, 그 뒤로 새로 오르는 차수만 그 시각을 적는다
- `equipOwned`: 장비 컬렉션에서 모은 아이템 ID 배열(보스 드롭·레벨 선물·장비 상점). 칸이 없던 예전 저장은 빈 배열이고, 컬렉션에 없는 ID 는 빼고 읽는다
- `equipWorn`: 자리(`cap`·`faceAccessory`·`eyeAccessory`·`earrings`·`top`·`overall`·`bottom`·`shoes`·`glove`·`shield`·`cape`·`weapon`) → 입은 컬렉션 아이템 ID. 가진 적 없거나 자리가 안 맞는 것은 버리고, 한벌옷과 상의·하의가 같이 있으면 나중 것만 남는다
- `equipPity`: 보스 몹 ID → `{ rare, veryRare }` 그 등급이 안 나온 채 잡은 수. 그 등급이 나오면 0 이다. 모르는 보스·음수·숫자가 아닌 값은 버린다
- `equipGifts`: 받은 레벨 선물 아이템 ID. 같은 선물을 두 번 주지 않는다. 칸이 없던 예전 저장은 빈 배열로 읽고, 켤 때 이미 넘은 레벨 선물을 받으며 채운다
- `chairOwned`: 보스가 떨어뜨려 모은 의자 아이템 ID 배열. 칸이 없던 예전 저장은 빈 배열이고, 의자 목록에 없는 ID·겹친 ID 는 빼고 읽는다
- `chairSelected`: 쉴 때 앉는 의자 ID. 없으면 `null`(의자 없이 선다). 가진 적 없는 의자거나 숫자가 아니면 `null` 로 읽는다
- `mountOwned`: 레벨 선물·보스 드롭으로 모은 탈것 아이템 ID 배열. 칸이 없던 예전 저장은 빈 배열이고, 탈것 목록에 없는 ID·겹친 ID 는 빼고 읽는다
- `mountSelected`: 돌아다니거나 맵을 옮길 때 타는 탈것 ID. 없으면 `null`(걷는다). 가진 적 없는 탈것이거나 숫자가 아니면 `null` 로 읽는다

예전 판은 캐릭터·설정을 WebView localStorage(`maple-companion:characters`·`maple-companion:settings`, 그 전에는 `maple-companion:save`)에 두었다. localStorage 는 앱마다 따로라(개발 빌드 `~/Library/WebKit/maple-companion/`, 배포 앱 `~/Library/WebKit/com.maplecompanion.app/`) 개발 빌드에서 키운 캐릭터가 배포 앱에서는 안 보였다. 지금 판은 켤 때 그 앱의 localStorage 를 아직 안 옮겼으면 `game-state.json` 과 합친다(`src/platform/gameState.ts`).

- 캐릭터는 id 로 합친다. 같은 캐릭터가 양쪽에 있으면 활동 시간 + 사냥 경험치가 큰 쪽을 쓰고 옷장은 합친다. 사냥 스킬·보스 지정도 큰 쪽 것이고, 전직 날짜는 차수마다 날짜가 있는 쪽(둘 다 있으면 이른 쪽)을 쓴다. 2차 갈래는 더 자란 쪽이 아니라 마지막으로 갈래를 바꾼 쪽, 바꾼 기록이 같으면 갈래를 정한 쪽(고른 뒤 다시 고르기에 답한 쪽)을 따른다. 그래서 갈래를 다른 쪽에서 가져오면 사냥 스킬은 자동으로 돌린다. 바꾼 기록은 양쪽을 합친다. 갈래 바꾸기 안내는 한쪽에서라도 띄웠으면 띄운 것이다. 장비 컬렉션과 받은 레벨 선물은 합치고, 입은 장비는 더 자란 쪽 것, 드롭 천장은 보스·등급마다 더 센 쪽이다. 모은 의자·탈것은 합치고 고른 의자·탈것은 더 자란 쪽 것이다(`mergeRosters`, `src/game/save.test.ts`)
- 고른 캐릭터·소리 끄기·설정은 파일에 이미 있으면 파일 값을 쓴다
- 다 옮기면 localStorage 에 `maple-companion:migrated-to-file` 표시를 남기고 다음부터는 파일만 읽는다. localStorage 값은 지우지 않고 백업으로 둔다
- 개발 빌드에서 키운 캐릭터는 새 판 개발 빌드를 한 번 켜면 옮겨진다. 배포 앱에서 키운 캐릭터는 새 판 배포 앱을 한 번 켜면 옮겨진다

브라우저로 화면만 볼 때(`pnpm dev`)는 지금처럼 localStorage 에만 저장한다.

## 리소스

캐릭터·몬스터·맵·BGM 은 저장소와 앱에 넣지 않는다. 실행 중에 팬 API [maplestory.io](https://maplestory.io) (KMS 389) 에서 받아 온다. 보내는 값은 공개된 맵·몹·아이템 ID 뿐이다.

맵·캐릭터·몹 그림은 받을 때 기기(IndexedDB)에 남기고 다음부터는 네트워크 없이 그것으로 그린다(`src/maple/artStore.ts`, 위 「저장 위치」). maplestory.io 는 `max-age=86400` 만 줘서 HTTP 캐시는 하루가 지나면 다시 받고, WebKit 디스크 캐시는 몇 MB 짜리 맵 렌더를 남기지 않는 일이 있어 앱이 따로 남긴다. 남긴 바이트를 그대로 읽어 그려서 받은 것과 그림이 같다. 5xx·깨진 그림은 남기지 않고, 남긴 것을 못 읽으면 지우고 다시 받는다. 처음 받을 때는 지금처럼 시간 제한(30초, 맵 렌더 90초) 안에 받는다. 캐릭터는 모습 그대로의 요청 주소가 키라 옷·헤어가 바뀌면 새로 받는다. 캐릭터가 보인 뒤 5초쯤 지나 지금 모습의 서기·걷기·공격·alert·점프·사다리·로프 동작을 하나씩 받아 둔다. 맵 렌더(약 3MB)도 Rust 파일이 아니라 IndexedDB 에 둔다. 예산 400MB 는 WebKit(macOS 14 이상 WKWebView 앱은 디스크의 15%까지)과 WebView2 한도 안이고, 그림이 한곳에 있어야 예산·지우기를 한 번에 하고 브라우저 개발 화면에서도 똑같이 돈다.

BGM 은 주소를 audio 에 바로 걸지 않고 곡을 통째로 받아 app data 의 `bgm/` 에 남긴 뒤 거기서 튼다(`src/audio/bgm.ts`, `src-tauri/src/bgm_cache.rs`). 바로 걸면 WebKit 이 곡을 구간마다 따로 받고 디스크 캐시에도 안 남겨서, 팬 API 가 늦거나 520 을 내면 곡 중간·반복 지점에서 끊겼다. 지금은 곡마다 처음 한 번만 받고 다음부터는 네트워크 없이 바로 튼다.

- 곡은 맵이 아니라 곡 경로(`Bgm00/FloralLife`)로 받고 남긴다. 주소는 `/music/{폴더}/{이름}` 이다. 여러 맵이 같은 곡이면(헤네시스·머쉬맘 맵은 둘 다 FloralLife) 한 번만 받는다
- 맵 → 곡은 `src/audio/bgmCatalog.ts` 의 `MAP_BGM`(마을·사냥터·통로·보스 맵 72곳)에서 바로 찾는다. 여기 없는 맵은 WZ 노드 `Map/Map/Map{앞자리}/{9자리 ID}.img/info/bgm` 값(곡 경로)을 읽어 기기(IndexedDB)에 남긴다. 못 읽으면 15초 뒤 다시 읽는다
- 곡 목록(`BGM_FOLDERS`)은 `scripts/curate-bgm.ts` 가 WZ 노드 `Sound` 와 `Sound/Bgm*.img` 의 자식 이름을 읽어 커밋해 둔 것이다. 팬 API 의 음악 목록 주소(`/music`)는 500 을 내고, WZ 목록은 72번 요청해야 해서 앱이 켤 때마다 받지 않는다. 이름과 경로만 담고 소리는 담지 않는다. 버전을 올리면 스크립트를 다시 돌린다
- 「맵 따라가기」 일 때만 곧 들어갈 만한 맵의 곡을 뒤에서 한 곡씩 미리 받아 둔다(`likelyBgmMaps`). 순서는 지금 마을의 사냥터, 셔플 백 순서 마을 네 곳(백이 없으면 레벨 높은 마을 네 곳), 잡을 수 있는 보스 전부(센 것부터), 나머지 열린 마을이다. 이미 남긴 곡은 건너뛰고, 지금 곡을 받는 동안에는 멈춘다. 실패한 곡은 5분 뒤 다시 받는다. 「즐겨찾기 무작위」 는 다음에 틀 곡 하나만, 「한 곡 반복」 은 아무것도 미리 받지 않는다. 고른 곡은 틀 때 처음 받는다
- 남긴 곡이 없는 곡으로 옮기면 앞 곡을 끊고 그 곡 주소를 바로 스트리밍한다. 다 받으면 받은 파일로 바꿔 듣던 자리부터 잇는다. 받기만 실패하면 15초 뒤 받기만 다시 한다
- 같은 곡을 다시 부르면 처음부터 다시 틀지 않는다
- 남긴 곡은 모두 합쳐 300MB(`BGM_CACHE_BUDGET_BYTES`)까지 둔다. 원작 곡은 한 곡에 대개 1~3MB 라 100곡 넘게 들어가고, 맵 따라가기가 미리 받는 곡(겹치는 곡이 많아 수십 곡)은 넉넉히 들어간다. 곡을 하나 남길 때마다 합계를 보고, 넘으면 마지막으로 쓰거나 읽은 때(파일 수정 시각, Rust 가 읽을 때 지금으로 바꾼다)가 오래된 곡부터 지운다. 지금 곡과 미리 받는 목록의 곡은 지우지 않아서, 그것만으로 넘으면 넘은 채 둔다. 맵 따라가기 곡과 고른 곡을 가리지 않고 같이 센다
- 예전 판이 맵 번호로 남긴 파일(`KMS-389-{맵 ID}.mp3`)은 켤 때 `MAP_BGM` 으로 곡을 찾아 곡 이름으로 옮긴다. 같은 곡이 이미 있으면 지운다. `MAP_BGM` 에 없는 맵의 파일은 그대로 두었다가 용량을 넘으면 오래된 순서대로 지워진다
- 브라우저(`pnpm dev`)에서는 Cache API(`maple-companion:bgm-tracks`)에 남긴다. 맵 주소로 남기던 예전 `maple-companion:bgm` 은 지운다

맵은 전체 렌더(`render/0`)를 캐릭터 뒤에 깔고, 위쪽 레이어를 따로 받아(`render/layer/{n}/0?minX=&minY=`) 캐릭터 앞에 그린다. 그래서 무릉 다리 난간 같은 앞쪽 타일·오브젝트가 캐릭터를 가린다. 앞 레이어는 마을이 뜨고 몇 초 뒤에 들어온다.

원작 범용 버튼(`src/ui/mapleButton.ts`): 원작 UI.wz 의 범용 버튼(`Basic.img`·`UtilDlgEx`·`UIWindow2` 스킬창 버튼·보스 UI 버튼)은 모두 글자가 그림에 박혀 있고, 글자 없는 버튼은 찾지 못했다. 그래서 상태 그림(normal·mouseOver·pressed·disabled)마다 글자가 없는 왼쪽 끝·가운데 열·오른쪽 끝만 canvas 로 떼어 띠를 만든다. 스킬 아이콘은 `src/game/skillBook.ts` 의 `skillIconPath` 경로(`Skill/_Canvas/{직업 번호}.img/skill/{7자리 ID}/icon`)로 바로 받는다. 바이퍼 4차·도적 일부처럼 아이콘 노드의 `_outlink` 가 다른 스킬(`112.img`·`40000.img` 등) 그림을 가리키는 것은 목록을 고를 때 링크를 미리 읽어 `icon` 으로 적어 두어서, 실행 중에 링크를 다시 받지 않는다. 받은 아이콘은 캐시샵처럼 IndexedDB(`src/ui/cashAssets.ts`)에 남겨 다음 실행부터는 네트워크 없이 그린다. 앱을 켤 때와 직업·차수가 바뀔 때 이 직업 길의 모든 탭 아이콘과 창 그림을 뒤에서 미리 받고(동시에 6개, 지금 차수 탭부터), 창을 열면 지금 탭 아이콘이 미리 받기보다 먼저 받아진다. 받는 동안 칸에는 옅은 회색 판을 둔다.

스킬 데이터(`/job/skill/{ID}`)는 이펙트 프레임이 base64 로 들어 있어 수백 KB~20MB 다. 받은 것은 그리는 데 쓰는 이름·사거리·타수·이펙트·동작만 남겨 같은 IndexedDB 에 버전(`KMS-389`)·스킬 ID 로 둔다(`src/maple/skillStore.ts`). 맵의 사냥 스킬도 같은 길로 받아서, 앱을 다시 켜도 네트워크 없이 바로 그린다. 5MB 가 넘는 스킬은 남기지 않고 쓸 때마다 받으며, 모두 합쳐 60MB 를 넘으면 가장 오래 안 쓴 스킬부터 지운다. 스킬창 아이콘을 다 받은 뒤에는 지금 차수 탭에서 쓰거나 사냥에 고를 수 있는 스킬과 지금 사냥 스킬의 데이터를 작은 것부터 한 번에 하나씩 뒤에서 받아 둔다(5MB 넘는 것은 건너뛴다). 크기 순서는 `skillBook.ts` 의 `kb`(목록을 고를 때 잰 응답 크기)로 정한다. 스킬 목록·이름은 `src/game/skillBook.ts` 에 적어 두었다: 1~4차는 `/job/{직업}/skillbook` 에서 숨김·하이퍼를 뺀 것(바이퍼 512 는 이 응답이 서버에서 터져 `Skill/512.img` 목록과 `/job/skill/{ID}` 로 같은 기준을 맞췄다), 5차는 `Etc/VCore.img/CoreData` 의 스킬 코어 중 그 직업·계열·모험가 공용인 것, 6차는 `Etc/HexaCore.img/hexaSkill/jobCore/{직업}` 의 스킬·마스터리 코어와 공용 솔 야누스다. 고를 수 있는지는 `/job/skill/{ID}` 의 `damage` 속성과 `effect` 프레임 수로 정했다. 1차는 계열이 같이 배우고 2~6차는 2차 갈래마다 따로다. 갈래를 넣으며 새로 뽑은 일곱 갈래(팔라딘·다크나이트·아크메이지(썬,콜)·비숍·신궁·섀도어·캡틴)는 같은 규칙으로 뽑았고, 같은 규칙으로 기존 히어로 목록을 다시 뽑아 똑같이 나오는 것을 확인했다. 다른 갈래와 겹치는 공용 V 코어는 기존 갈래의 분류·크기를 따른다. 아이콘 289개는 모두 받아지는 것을 확인했다 달팽이 세마리(1000)는 `/job/skill` 이 500 을 내서 초보자는 고를 공격 스킬이 없다.

HUD 의 스탯·스킬 버튼은 옆 캐시샵·⚙️ 버튼과 같은 어두운 칸이다. 안의 그림은 빅뱅 전 상태 바 단축 버튼 `UI/StatusBar.img/StatKey`·`SkillKey`(28×20)에서 파란 바탕을 빼고 떼어 낸 막대그래프(16×12)·책(18×12)을 원본 크기로 넣는다(`src/ui/glyph.ts`, 실행 중에 canvas 로 뗀다). 뗀 그림은 기기에 남겨 다음 실행부터 네트워크 없이 바로 넣는다. 받기 전에는 「스탯」「스킬」「보스」 글자 버튼이고, 켤 때 maplestory.io 가 멈춰 있어도 위 「저장 위치」의 간격으로 다시 받아 그림으로 바꾼다. 바탕 판정은 「파랑이 빨강·초록보다 40 넘게 큼」이라 그림의 하늘색 테두리·청록 막대는 남는다. 지금 상태 바(`StatusBar3.img/mainBar/menu`)의 메뉴 버튼은 34×37 파란 버튼이고, 키 설정 아이콘(`StatusBar3.img/KeyConfig/icon`)은 글자 타일이라 그림만 뗄 수 없어 쓰지 않았다.

메뉴바 트레이 아이콘은 아이템 「단풍잎」(4001126) 아이콘이다. 프론트가 받아 Rust 에 넘기고, Rust 는 app data 의 `tray-icon.png` 에 저장해 다음 실행부터 네트워크 없이 바로 쓴다. 못 받으면 기본 아이콘이 남는다. 같은 폴더에 `custom-tray-icon.png` 를 두면 그 그림이 먼저 쓰이고 단풍잎은 내려받아도 덮어쓰지 않는다(36×36 PNG 권장, 지우면 단풍잎으로 돌아간다). 저장소의 번들 아이콘(`src-tauri/icons`)은 Tauri 기본 아이콘 그대로 둔다. 넥슨 그림은 릴리스 빌드에만 넣는다(아래 「릴리스 앱 아이콘」).

릴리스 앱 아이콘은 버섯집 그림이다. GitHub Actions 릴리스 빌드에서만 넣고, 저장소에는 그림 파일을 두지 않는다.

- 그림은 관리자가 저장소 시크릿 `RELEASE_ICON_PNG_BASE64` 에 넣어 둔다. 값은 PNG 파일의 base64 다. `base64 -i <file> | tr -d '\n'` 로 만들어 GitHub 저장소 Settings → Secrets and variables → Actions 에 붙여 넣는다. PNG 는 8비트 RGBA·RGB·팔레트를 읽는다
- `macos`·`windows` 잡이 빌드 전에 `scripts/release-icon.ts` 를 돌린다. 시크릿의 그림을 쓰고, 시크릿이 비어 있으면 스크립트의 `SOURCE_URL` 에서 받는다(지금은 비어 있다. 한 번에 30초, 5xx·시간 초과면 4번까지). 그림을 아래 앱 아이콘과 같은 규칙으로 1024×1024 에 늘리고, `tauri icon` 으로 `src-tauri/icons-release/`(.gitignore)에 `icon.icns`·`icon.ico`·PNG 를 만든다
- 빌드는 `--config src-tauri/icons-release/release-icon.conf.json` 으로 `bundle.icon` 만 바꾼다. `tauri.conf.json` 과 `src-tauri/icons` 는 그대로다. 알림 왼쪽 아이콘·Dock·앱 전환기·Finder·Spotlight·exe·시작 메뉴·설치 프로그램·Windows 알림이 모두 이 아이콘으로 나온다
- 같은 단계가 `MAPLE_BUNDLED_ICON=1` 을 걸고 빌드한다. 앱은 컴파일할 때 이 값을 읽어(`app_icon::BUNDLED_ICON`) 실행 중에 앱 아이콘을 붙이지 않고 알림 오른쪽 그림도 넣지 않는다
- 그림이 없거나 못 읽으면 경고만 남기고 기본 아이콘으로 빌드한다. 그 빌드와 로컬 빌드(`pnpm tauri dev`·`pnpm tauri build`)는 기본 아이콘이라 아래처럼 실행 중에 붙인다

번들 아이콘이 기본 그림인 빌드는 앱 아이콘(Finder·Spotlight)을 macOS 에서만 트레이 아이콘과 같은 그림으로 바꾼다. 각자의 컴퓨터에서 실행 중에 붙인다(`src-tauri/src/app_icon.rs`).

- 트레이 그림(`custom-tray-icon.png` 가 있으면 그것, 없으면 `tray-icon.png`)의 투명한 가장자리를 잘라 내고 1024×1024 의 가운데 824px 안에 들어가도록 정수배로 늘린다. 픽셀 그림이라 이웃 픽셀을 섞지 않는다
- `NSWorkspace.setIcon(_:forFile:)` 으로 설치된 `.app` 에 Finder 사용자 아이콘을 붙인다. 번들 맨 위에 `Icon\r` 파일이 생기고 번들 폴더에 FinderInfo 확장 속성이 붙는다. 실행 중인 앱 아이콘(`NSApplication.applicationIconImage`)도 같은 그림으로 바꾼다
- 붙인 그림의 해시를 app data 의 `app-icon-applied.txt` 에 남겨, 그림이 같고 `Icon\r` 이 남아 있으면 다시 쓰지 않는다. 업데이트는 `.app` 을 통째로 바꿔 넣어 아이콘이 사라지므로 다음 실행에서 다시 붙인다
- `.app` 이 아닌 곳에서 띄운 개발 실행(`pnpm tauri dev`)은 번들이 없어 붙이지 않는다. 디스크 이미지 안에서 바로 띄우거나 macOS 가 앱 수정을 막는 등 번들에 쓸 수 없으면 로그만 남기고 기본 아이콘을 둔다. 실패도 `app-icon-applied.txt` 에 남겨, 차단 알림이 실행할 때마다 뜨지 않도록 그림이 바뀌거나 번들 폴더가 바뀔 때(업데이트·다시 설치로 inode 가 달라질 때)까지 다시 해 보지 않는다
- 코드 서명: `codesign --verify` 는 그대로 통과한다. `--strict` 는 번들 폴더의 FinderInfo 때문에 실패한다. 실행 파일 서명은 바뀌지 않고, 업데이트는 받은 압축 파일의 서명만 확인하므로 영향이 없다
- Windows 시작 메뉴·작업표시줄 아이콘은 exe 안의 리소스라 실행 중에 바꿀 수 없다. 창 아이콘(Alt+Tab)만 같은 그림으로 바꾼다

OS 알림의 그림도 macOS 에서는 앱 아이콘과 같은 그림을 쓴다(`src-tauri/src/notification.rs`). 번들 아이콘이 기본 그림인 빌드는 알림 왼쪽 아이콘을 바꿀 수 없어서 오른쪽 그림으로 넣는다. 릴리스 빌드는 왼쪽이 이미 버섯집이라 오른쪽 그림을 넣지 않는다.

- macOS 알림 센터는 왼쪽 아이콘을 번들의 `Contents/Resources/icon.icns`(Info.plist 의 `CFBundleIconFile`)로만 그린다. Finder 사용자 아이콘, 실행 중인 앱 아이콘, NSUserNotification 의 비공개 키 `_identityImage`(mac-notification-sys 의 `app_icon`)는 모두 무시된다. macOS 26.5.1 에서 테스트 알림을 띄워 확인했다
- `icon.icns` 를 실행 중에 바꿔 쓰면 코드 서명의 리소스 봉인이 깨진다(`codesign --verify` 가 「a sealed resource is missing or invalid」로 실패). 업데이트마다 번들이 통째로 바뀌어 다시 써야 하므로 쓰지 않는다. 버섯집 아이콘은 릴리스 빌드에서 번들에 넣는다(위 「릴리스 앱 아이콘」)
- 그래서 알림 오른쪽 그림(`contentImage`)에 앱 아이콘 캔버스(1024×1024, 가운데 824px)를 넣는다. 트레이 그림으로 app data 의 `notification-image.png` 를 만들고, 그림이 바뀌었을 때만 다시 쓴다
- tauri-plugin-notification 은 macOS 에서 이 그림을 넘길 길이 없어, 프론트는 Rust 명령 `show_notification` 을 부르고 Rust 가 mac-notification-sys 로 직접 보낸다. 보내는 앱은 플러그인과 같다(설치한 앱은 `com.maplecompanion.app`, `pnpm tauri dev` 는 터미널)
- 알림을 누를 때까지 기다리게 보내야 누른 것을 받는다. 알림마다 스레드 하나가 기다리고, 알림을 누르거나 알림 센터에서 지우면 끝난다. 누르면 창이 열린다
- 트레이 그림이 없거나 그림 파일을 못 쓰면 그림 없이 보낸다. 명령이 실패하면 프론트가 플러그인으로 그림 없는 알림을 띄운다
- Windows 는 플러그인 그대로 띄운다. 플러그인은 토스트에 그림을 넘기지 않아 시작 메뉴 바로가기의 앱 아이콘이 나온다

사냥터 연결은 `scripts/curate-routes.ts` 가 미리 골라 `src/game/routeData.ts` 에 적어 둔다(아래 「개발」). 맵 정보 API(`/map/{ID}`)의 `portals` 는 스크립트가 붙은 포털(마을 밖으로 나가는 `east00`·`west00` 등)을 `null` 로 내려서, 포털은 WZ 노드 `Map/Map/Map{앞자리}/{9자리 ID}.img/portal/{n}` 의 `pn`·`tm`·`tn`·`x`·`y` 로 읽는다. 포털까지는 발판 길(`src/maple/navigation.ts`)로 간다. 맵 정보의 `footholds`(prev/next 로 이어진 묶음, 벽은 x1 = x2)와 `ladderRopes`(x, 위 끝 y1, 아래 끝 y2, 사다리/로프)로 이음을 만든다.
- 걷기: 같은 발판 묶음 위. 벽에서 끊긴다
- 떨어지기: 묶음 끝에서 걸어 나간다. 위로 솟은 벽에 막힌 끝은 안 된다. 내릴 발판이 없으면(맵 밖) 이음을 만들지 않는다
- 아래 점프: 바로 밑 발판으로 뚫고 내려간다(600px 까지)
- 점프: Map.wz `Physics.img` 값(점프 속도 555, 중력 2000, 낙하 최고 속도 670, 걷기 125)으로 궤적을 계산해 실제로 그 발판에 내리는 것만 쓴다. 오를 수 있는 높이는 약 70px 다
- 사다리·로프: 위 끝 y1 이 발판 높이와 같고, 아래 끝 y2 는 밑 발판에서 80px 안에 떠 있다. 위아래가 다 발판에 닿는 것만 쓴다

나가는 포털과 건너편 맵의 도착 포털은 모두 바로 아래(60px 안)에 발판이 있고, 사냥하는 바닥(가장 긴 발판 묶음)에서 그 포털까지 가는 길과 거기서 바닥으로 돌아오는 길이 둘 다 있어야 쓴다. 실행 중에는 같은 계산으로 길을 찾아 움직이고, 공중 구간도 같은 계산으로 날아 같은 자리에 내린다. 60초 안에 못 가면 그 자리에서 포털에 들어가고, 내려오는 길이 끊기면 바닥으로 옮겨 세운다. 포털에 닿은 뒤 화면이 어두워지는 동안과 건너편 포털에서 화면이 밝아지는 동안은 그 포털 발판에 그대로 서 있는다. 예전에는 이 사이에 바닥 높이로 끌어내려져, 윗층 포털에서 바닥으로 떨어졌다가 다시 올라가 보였다. 캐릭터 동작은 `jump`·`ladder`·`rope` 를 받아 쓰고 못 받으면 서기·걷기 그림으로 움직인다. 바닥보다 높은 레이어 발판에 서 있는 동안은 앞 레이어를 감춘다(그 발판 그림이 캐릭터를 가려서). 몬스터와 사냥은 지금처럼 바닥에서만 한다. 몬스터는 맵 정보의 `mobs` 에서 스폰 자리가 많은 순으로 넷까지 고른다.

사냥터 레벨은 그 몬스터 레벨(`/mob/{ID}` 의 `meta.level`)의 가운데값이다. 마을마다 아래 순서로 고르고, 앞 단계에서 하나라도 고르면 멈춘다.

1. 레벨이 마을 레벨 −10 ~ 다음 마을 레벨 +15(다음 마을이 없으면 마을 레벨 +40) 안인 사냥터만, 통로 없이 고른다. 사냥터는 마을에서 포털 셋째 칸까지 본다
2. 같은 레벨 폭으로 몹이 없는 맵을 통로로 지나가 본다. 통로는 둘까지 이어 지나고 사냥터 칸 수에 세지 않는다. 앱 마을이 아닌 마을 맵(상점·무릉 사원 등)도 통로로 지난다. 통로는 그 너머 사냥터를 골랐을 때만 경로에 넣는다
3. 그래도 없으면 위 끝을 마을 레벨 +60 으로 넓혀 다시 고른다(`relaxedLevelBand`). KMS 389 는 오르비스·엘나스·루디브리엄 둘레 사냥터가 70~110 대라 마을이 열리는 레벨과 멀다. 사냥터 몬스터는 그림만 바뀌고 경험치·메소는 지금처럼 마을·레벨 기준이라 벌이는 그대로다

## 개발

```bash
pnpm install
pnpm tauri dev                 # 앱
MAPLE_SPEED=60 pnpm tauri dev  # 60배속으로 경험치 확인
pnpm dev                       # 브라우저로 화면만 (http://localhost:1420/?speed=60)
                               # ?boss=8860000 이면 그 보스(?boss=1 이면 레벨에 맞는 보스)와 바로 싸운다. 개발 서버에서만
pnpm test                      # 단위 테스트
node --experimental-strip-types scripts/curate-routes.ts [캐시 폴더]   # 마을 사냥터 다시 고르기 → src/game/routeData.ts
node --experimental-strip-types scripts/curate-bgm.ts [캐시 폴더]      # 원작 BGM 목록·맵 곡 다시 읽기 → src/audio/bgmCatalog.ts
node --experimental-strip-types scripts/release-icon.ts [그림 PNG]      # 릴리스 앱 아이콘 → src-tauri/icons-release (CI 는 시크릿으로 돌린다)
pnpm tauri build --target universal-apple-darwin   # 배포용 .app·.dmg (src-tauri/target/universal-apple-darwin/release/bundle)
pnpm tauri build               # Windows 에서 실행하면 -setup.exe·.msi (src-tauri/target/release/bundle/nsis·msi)
```

배포는 `v*` 태그를 푸시하면 GitHub Actions(`.github/workflows/release.yml`)가 돈다. `release` 잡이 릴리스를 먼저 만들고, 그 뒤 `macos` 잡(macos-latest)이 유니버설 앱 `.dmg`·`.zip`·`.app.tar.gz` 를, `windows` 잡(windows-latest)이 `-setup.exe`(NSIS)·`.msi` 를 같은 릴리스에 올린다. 두 잡이 릴리스를 각자 만들지 않아서 둘이 생기거나 서로 부딪치지 않는다. Actions 화면에서 「Run workflow」로 수동 실행하면 Windows 빌드만 돌고, 설치 파일은 릴리스가 아니라 그 실행의 Artifacts(`maple-companion-windows`)에 올라간다. macOS 서명은 ad-hoc(`bundle.macOS.signingIdentity: "-"`)이고 공증은 하지 않는다. Windows 는 서명하지 않는다. 버전은 `package.json`·`src-tauri/tauri.conf.json`·`src-tauri/Cargo.toml` 세 곳을 같이 올린다.

### 업데이트 서명

앱 안 업데이트(「업데이트」 절)는 업데이트 파일을 서명키로 서명해 올리고 앱이 공개키로 확인한다.

- 공개키는 `src-tauri/tauri.conf.json` 의 `plugins.updater.pubkey` 에 있다. 비밀키는 저장소 밖 `~/.tauri/maple-companion.key` 에 있고 비밀번호는 없다(`pnpm tauri signer generate -w ~/.tauri/maple-companion.key` 로 만들었다)
- 태그를 푸시하기 전에 GitHub 저장소 Settings → Secrets and variables → Actions 에 `TAURI_SIGNING_PRIVATE_KEY` 를 등록한다. 값은 `~/.tauri/maple-companion.key` 파일 내용 전체다. 비밀번호가 없는 키라 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 는 등록하지 않는다. 워크플로가 둘 다 넘기는데 등록하지 않은 시크릿은 빈 문자열로 들어간다
- `bundle.createUpdaterArtifacts` 를 켜 두어서 비밀키가 없으면 빌드가 서명 단계에서 실패한다. 손으로 빌드할 때는 `TAURI_SIGNING_PRIVATE_KEY=~/.tauri/maple-companion.key pnpm tauri build ...` 처럼 붙인다
- `latest.json` 은 tauri-action 이 만들어 릴리스에 올린다. `macos` 잡이 유니버설 `.app.tar.gz` 로 `darwin-aarch64`·`darwin-x86_64` 를 넣고, `windows` 잡이 `-setup.exe`(`updaterJsonPreferNsis`)로 `windows-x86_64` 를 더한다. tauri-action 은 이미 올라간 `latest.json` 을 받아 자기 플랫폼을 더해 다시 올려서, 두 잡이 동시에 끝나면 한쪽이 빠진다. 그래서 `windows` 잡은 `macos` 잡이 끝난 뒤에 돈다
- **비밀키를 백업한다.** 키 파일을 비밀번호 관리자 같은 저장소 밖 안전한 곳에 한 벌 더 둔다. 키를 잃으면 이미 설치된 앱은 새 업데이트의 서명을 확인할 수 없어 다시는 앱 안에서 업데이트하지 못한다. 새 키로 바꾸면 모든 사용자가 한 번 손으로 다시 설치해야 한다

Rust 가 필요하다(`rustup`). 트레이 아이콘은 왼쪽·오른쪽 클릭 모두 같은 메뉴를 연다. 메뉴 맨 위 항목이 창을 띄우거나 숨긴다. 글자는 모드와 창 상태에 따라 바뀐다(펫 모드는 「캐릭터 숨기기/보이기」, 메뉴바 모드는 「창 닫기/열기」). 그 아래에서 펫 모드(화면 구석 창)와 메뉴바 모드(메뉴바 아이콘 아래에 여는 창)를 바꾸고, 지금 모드에 체크가 붙는다. 메뉴바 모드에서 아이콘 위치를 아직 모르면 화면 오른쪽 위에 연다. Windows 는 메뉴바 모드 창을 트레이 아이콘 위로 열고(화면 밖으로 나가면 모니터 안으로 당긴다), 아이콘 위치를 모르거나 펫 모드일 때는 작업표시줄을 뺀 영역의 오른쪽 아래 구석에 둔다. 테두리 없는 창도 Alt+F4 로 닫히므로 닫기는 숨기기로 바꿨다.

트레이 메뉴 「설정」은 창을 띄우고 설정 화면을 연다(맵 화면일 때만). 트레이 메뉴 「창 크기」에서 창 크기를 75%~200% 로 고른다. 고른 크기는 다음 실행에도 남는다. 100% 이상은 캐릭터·몬스터·HUD 크기는 그대로 두고 맵을 더 넓게 보여 준다. HUD 와 경험치 바는 창 폭만큼 늘고, 캐릭터 정보·스킬·보스·BGM·설정 창과 캐릭터 선택은 360×230 크기 그대로 가운데에 뜬다. 캐시샵은 창을 다 채우고 칸 수를 늘린다. 맵이 화면보다 좁거나 낮으면 가운데·아래에 두고 남는 곳은 하늘색으로 채운다. 75% 는 화면 전체를 통째로 줄인다. 브라우저로 볼 때는 `?scale=1.5` 를 붙이고 브라우저 창을 그 크기(540×345)로 맞춘다.
